2. Types Reference

The data types described in this section are declared in pittpatt_detection.h, with the exception of ppr_error_type, which is declared in pittpatt_errors.h.

Basic Types

ppr_context_type

typedef ppr_context_struct* ppr_context_type;

The ppr_context_type is a handle that references private data maintained internally by the SDK library. Most of the SDK functions take a context as the first parameter. Multiple contexts allow the SDK to be used with different sets of parameters or inside of different threads within the same process.

A new handle is returned by the ppr_get_context function. When a context is no longer needed, it must be released with a call to ppr_release_context.

See also: Contexts

Back to top.

ppr_image_type

typedef ppr_image_struct* ppr_image_type;

The SDK functions operate on images of type ppr_image_type. However, images are read from disk in the ppr_raw_image_type format. Use ppr_create_image to create a ppr_image_type from a ppr_raw_image_type.

See also: Image Types

Enumerated Types

ppr_coarse_detector_mask_type

typedef enum 
{
  PPR_FRONTAL_DETECTOR_MASK            = 0x01,
  PPR_RIGHT_PROFILE_DETECTOR_MASK      = 0x02,
  PPR_LEFT_PROFILE_DETECTOR_MASK       = 0x04,
  PPR_FRONTAL_TILTED_N30_DETECTOR_MASK = 0x08,
  PPR_FRONTAL_TILTED_P30_DETECTOR_MASK = 0x10,
  PPR_ALL_FACE_DETECTORS_MASK          = 0x1F,
} ppr_coarse_detector_mask_type;

This enumeration defines binary masks used to specify a set of coarse-precision detectors. Values can be combined using binary OR operators to select any number of available detectors. For example, the two profile detectors can be specified using the following expression: 

PPR_RIGHT_PROFILE_DETECTOR_MASK | PPR_LEFT_PROFILE_DETECTOR_MASK

As a shortcut to easily specify all of the face detectors, the ALL_FACE_DETECTORS_MASK value is provided.

The set of coarse-precision detectors can be set using ppr_set_coarse_detector_types. This only applies when using coarse-precision detection. To select coarse or fine precision, use ppr_set_detection_precision.

See also: Detection Precision

Back to top.

ppr_landmark_detector_type

typedef enum 
{
  PPR_NO_LANDMARK_DETECTOR,
  PPR_FRONTAL_LANDMARK_DETECTOR,
  PPR_MULTI_POSE_LANDMARK_DETECTOR,
  PPR_DUAL_FRONTAL_LANDMARK_DETECTOR,
  PPR_DUAL_MULTI_POSE_LANDMARK_DETECTOR
} ppr_landmark_detector_type;

This enumeration defines the types of landmark detectors. The landmark detector type can be specified using ppr_set_landmark_detector_type. Landmark detector options that use multi-pose landmark detection must also use fine precision. The detection precision can be set using ppr_set_detection_precision.

PPR_NO_LANDMARK_DETECTOR

This option does not initialize the landmark detector. Memory usage is less than if landmark detection is enabled, but faces cannot be submitted for landmark detection. The ppr_detect_objects and ppr_detect_and_track_objects functions will not return landmarks, even if PPR_AUTOMATIC_LANDMARKS is set. Calls to ppr_detect_landmarks_from_object will return an error.

PPR_FRONTAL_LANDMARK_DETECTOR

This option initializes the frontal landmark detector. All functions that detect landmarks will use the frontal landmark detector. This is the only landmark detector option that can be used with coarse detection precision.

PPR_MULTI_POSE_LANDMARK_DETECTOR

This option initializes the multi-pose landmark detector. All functions that detect landmarks will use the multi-pose landmark detector. This option allows landmarks to be found even when the pose is not frontal. This landmark detector requires that fine precision is used.

PPR_DUAL_FRONTAL_LANDMARK_DETECTOR

This option initializes the frontal and multi-pose landmark detectors. When detecting landmarks, the frontal landmark detector is used first. If the frontal landmark detector finds landmarks, processing is complete and the detected landmarks are returned. If the frontal landmark detector is unable to find landmarks, the multi-pose landmark detector is then used, but it only searches for frontal landmarks. This method gives the best chance of finding frontal landmarks because sometimes frontal landmarks that are missed using the frontal landmark detector can be found using the multi-pose landmark detector. This landmark detector option requires that fine precision is used.

PPR_DUAL_MULTI_POSE_LANDMARK_DETECTOR

This option initializes the frontal and multi-pose landmark detectors. When detecting landmarks, the frontal landmark detector is used first. If the frontal landmark detector finds landmarks, processing is complete, and the detected landmarks are returned. If the frontal landmark detector is unable to find landmarks, the multi-pose landmark detector is used, searching for landmarks across all poses. This method gives the best possible multi-pose landmarks because if frontal landmarks can be found with the frontal detector, they are typically better than frontal landmarks detected with the multi-pose detector. Unlike the PPR_DUAL_FRONTAL_LANDMARK_DETECTOR option, landmarks from non-frontal poses can be returned if frontal landmarks are not present. However, this comes at the expense of additional execution time. This landmark detector option requires that fine precision is used.

See also: Landmarks, Detection Precision

Back to top.

ppr_landmark_category_type

typedef enum 
{
  PPR_LANDMARK_LEFT_EYE,
  PPR_LANDMARK_RIGHT_EYE,
  PPR_LANDMARK_NOSE_BASE,
  PPR_LANDMARK_NOSE_BRIDGE,
  PPR_LANDMARK_NOSE_TIP,
  PPR_LANDMARK_NOSE_TOP,
  PPR_LANDMARK_EYE_NOSE,
  PPR_LANDMARK_MOUTH
} ppr_landmark_category_type;

This enumeration defines the types of landmarks that can be detected on a face. The types of landmarks that can be detected varies with pose. See the figures in the Landmarks section for a visual depiction of the various landmarks.

PPR_LANDMARK_LEFT_EYE

The subject's left eye, defined as the midpoint between the eye corners.

PPR_LANDMARK_RIGHT_EYE

The subject's right eye, defined as the midpoint between the eye corners.

PPR_LANDMARK_NOSE_BASE

The lowest point along the vertical axis of the nose.

PPR_LANDMARK_NOSE_BRIDGE

Point along nose approximately midway between the nose top and nose tip.

PPR_LANDMARK_NOSE_TIP

Point along nose that is the furthest from the face plane.

PPR_LANDMARK_NOSE_TOP

Point on nose that is approximately midway between the subject's eyes.

PPR_LANDMARK_EYE_NOSE

Midpoint between the nose base and the center of the eye cavity.

PPR_LANDMARK_MOUTH

Point just below the bottom lip.

ppr_polygon_type

typedef struct
{
  int num_points;
  ppr_coordinate_type *points;
} ppr_polygon_type;

The ppr_polygon_type represents a list of points that form a polygon. The polygon points are in a clockwise order such that drawing a line between consecutive points (and from the last point back to the first point) yields a closed polygon. The structure is returned by ppr_get_object_boundary and must be freed using ppr_free_polygon.

int num_points

Number of points in the polygon.

ppr_coordinate_type *points

Array of points in the polygon.

ppr_object_type

typedef struct
{
  int model_id;
  ppr_coordinate_type position;
  ppr_dimensions_type dimensions;
  ppr_rotation_type rotation;
  float size;
  float confidence;
  int num_landmarks;
  ppr_landmark_type *landmarks;
} ppr_object_type;

This structure represents a single object detected by the SDK.

int model_id

Specific detector that found the object. The user should not manipulate this value. It is provided because it is needed by the SDK functions internally.

ppr_coordinate_type position

Position of the object within the image.

ppr_dimensions_type dimensions

Dimensions of the object in pixels.

ppr_rotation_type rotation

Rotation of the object within the image.

float size

Size of the object used internally by the detector.

float confidence

Likelihood that the object corresponds to a correct detection. For a detection context, the threshold parameter controls which detected objects are reported: objects with a confidence below the provided threshold will not be reported.

There is always some chance that an object reported by a particular detector is not actually present — for example, a false detection from a face detector would erroneously report a face in a location where no face is visible. The confidence field is normalized such that a value of zero corresponds to the equal error rate of the detector (i.e., approximately equal number of misses and false alarms). Larger values suggest a greater confidence in the correctness of the corresponding detection.

int num_landmarks

Number of landmarks detected.

ppr_landmark_type *landmarks

Array of landmark structures.

See also: Interpreting Results, Objects

Back to top.

Finds the best frontal face object in the input image. If a frontal face with landmarks is found, the output list will contain exactly one object. Miscellaneous Functions

ppr_get_object_boundary

ppr_error_type ppr_get_object_boundary( ppr_object_type  object,
  ppr_bounding_box_type  bounding_box,
  ppr_polygon_type  *polygon);
Parameters

object - object to get the boundary of

bounding_box - type of bounding box to use

polygon - pointer to the bounding polygon

Returns

error code

Restrictions

none

Extracts the points defining the polygon in which the object is located. The polygon points are returned in a clockwise order such that drawing a line between consecutive points (and from the last point back to the first point) yields a polygon encompassing the object. Frontal faces are described by rectangles. Left and right profile faces are described by oriented pentagons pointing in the direction of gaze. The bounding_box parameter specifies how close the bounding box will be mapped to each object. When using fine precision, the bounding boxes are rotated according to the estimated roll of the object.

The resulting polygon must be freed using ppr_free_polygon.

Note

For objects near the border of the image, the returned coordinates may fall outside of the bounds of the image.

See also: Objects
