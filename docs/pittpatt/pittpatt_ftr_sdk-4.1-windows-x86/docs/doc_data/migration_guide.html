Version 4.0 of the FTR-SDK introduced updates that require changes to code that uses the 3.x versions of the SDK. This guide explains the updates that require code changes, including the reason for the updates and the steps that must be taken to bring source code up to date.

1. Changes to pittpatt_detection_tracking.h

The constants, types, and functions defined pittpatt_detection_tracking.h were split into two files: pittpatt_detection.h and pittpatt_tracking.h. Constants, types, and functions used exclusively for tracking can now be found in pittpatt_tracking.h. Everything else is in pittpatt_detection.h. The reason for this split was to better group similar functions together.

Back to top.

2. Moved ppr_cluster_gallery to pittpatt_clustering.h

With the addition of multi-gallery clustering, a separate header file, pittpatt_clustering.h, was created to keep pittpatt_recognition.h from becoming too large. Therefore, ppr_cluster_gallery was moved from pittpatt_recognition.h to pittpatt_clustering.h.

Back to top.

3. New way to acquire contexts

The ppr_get_detection_context and ppr_get_tracking_context functions for getting a context for either detection or tracking have been replaced with a single function, ppr_get_context. Calling ppr_enable_tracking before initializing the context will enable the context to call the tracking functions. This mirrors the way that recognition gets enabled in a context.

Back to top.

4. All 'ppr_update' prefixes renamed to 'ppr_set'

All of the ppr_update function prefixes were renamed to ppr_set. This change was made in order to eliminate possible confusion. Now all of the functions for changing parameters start with ppr_set.

Back to top.

5. Change to how object size is reported

The size of an object was reported as a scale_factor, nominal_width, and nominal_height where the actual width of an object was computed by multiplying the scale_factor by the nominal_width (and similarly for the height). The size is now reported by the ppr_dimensions_type which contains the actual width and height of the object. This change, and the addition of ppr_get_size_from_pixels, simplifies how object sizes are reported and how min/max object sizes are specified.

Changes to ppr_object_type

Removed scale_factor, nominal_width, and nominal_height and added dimensions.

Changes to ppr_landmark_type

Removed scale_factor, nominal_width, and nominal_height since landmarks should not have a size associated with them since they are point-features.

Changes to ppr_track_summary_type

Replaced min_scale_factor, max_scale_factor, and avg_scale_factor with min_dimensions, max_dimensions, and avg_dimensions.

Back to top.

6. Setting number of threads changed

The ppr_set_num_threads function was split into two functions: ppr_set_num_detection_threads and ppr_set_num_recognition_threads The ppr_set_num_detection_threads function sets the number of worker threads used for detection while the ppr_set_num_recognition_threads function sets the number of worker threads used for recognition. This changed was made in order to give the end user more control over how worker threads are allocated.

Back to top.

7. Enabling shot boundary detection changed

The ppr_enable_shot_boundary_detection function used to take a threshold as input. Now it no longer takes the threshold as input, and ppr_set_shot_boundary_threshold has been added as the way to set the shot boundary threshold. This change makes shot boundary detection more consistent with the other functions in the SDK.

Back to top.

8. Disable template compression removed

The size of templates was drastically reduced in version 4.0 (when compared to version 3.1). This allowed us to remove the concept of template compression from the SDK. As a result, the ppr_disable_template_compression function was removed.

Back to top.

9. Argument order for ppr_set_template_string changed

The argument order for ppr_set_template_string was changed. Instead of context, string, template, it was changed to context, template, string. This matches other SDK functions where the parameter being modified comes before the setting that is being set.

Back to top.

10. Renamed ppr_object_suitable_for_recognition

The ppr_object_suitable_for_recognition function was renamed to ppr_is_object_suitable_for_recognition. This change matches the prefix convention of the other query functions.

Back to top.

11. Renamed ppr_get_ranked_subject_list

The ppr_get_ranked_subject_list function was renamed to ppr_get_ranked_subject_list_for_subject. This change was made to clarify the behavior of this function and to make it consistent with the other ranked list functions.

Back to top.

12. Arguments passed to ppr_copy_template_to_gallery changed

When a template is copied to a gallery, its ID is now returned via a reference argument rather than by setting the ID inside the template. Therefore, the template argument to the ppr_copy_template_to_gallery function is now passed by copy. Also, it now also takes a pointer to the ID that will be assigned to the template. This change obsoletes the ppr_get_template_id, and as a result, it has been removed from the SDK.

Back to top.

13. Prefix added to constants

The PPR_ prefix was added to PPR_MAX_CLUSTERING_AGGRESSIVENESS and PPR_MAX_TEMPLATE_STRING_SIZE. This change was made to match all of the other constants which start with PPR_.

Back to top.

14. SDK utils changes

The sdk_utils_copy_image_templates_to_gallery function was removed because it was only used by one example program, and it ended up masking the whole purpose of the example program.

The sdk_utils_write_template_id_list_thumbnails takes an extra argument, write_source_images. This parameter controls whether or not to write the source_image.txt text file.

The addition of text overlay drawing functions required splitting out the drawing functions into a separate file to prevent sdk_utils.c from becoming too large. The sdk_draw_utils.c file was created for this purpose and it needs to be compiled and linked with any programs that use sdk_utils.c. The sdk_utils_draw_line, sdk_utils_draw_cross, and sdk_utils_draw_polygon functions were moved to the new file and their prefixes were changed from sdk_utils_ to sdk_draw_utils_.

The sdk_draw_utils_line_attributes data structure was created to hold line attributes such as the color, line type, and thickness. This was done to keep the function argument lists from becoming too long. Some overlay and drawing functions now take the line attributes structure in place of several arguments.

With the addition of text overlays, the sdk_utils_overlay_object function now takes an extra argument that specifies a string to be written below the bounding box overlay. An empty string can be passed if a text overlay is not desired.

The addition of text overlays also allows frame numbers to be overlaid on the output of tracking programs. The sdk_utils_overlay_completed_track_list_on_image_list and sdk_utils_overlay_completed_track_list_on_video functions each take a flag that indicates whether frame numbers should be overlaid on the output.

Back to top.

15. Changes to Video I/O Library

The ppr_video_ prefix for all functions and types was changed to ppr_video_io_ to reflect the addition of video encoding and the name of the library file.

The ppr_video_initialize function was replaced with ppr_video_io_set_logging_type since this more accurately describes the behavior of this function.

The ppr_video_frame_available function was renamed to ppr_video_io_is_frame_available to be consistent with the other SDK query functions.
