Tracking Cutoff Constants

PPR_TRACKING_CUTOFF_MIN

#define PPR_TRACKING_CUTOFF_MIN -5

The PPR_TRACKING_CUTOFF_MIN constant specifies the minimum allowable cutoff value that can be passed to ppr_set_tracking_cutoff. This is the most permissive tracking cutoff.

See also: Tracking Cutoff

#define PPR_TRACKING_CUTOFF_MAX 5

The PPR_TRACKING_CUTOFF_MAX constant specifies the maximum allowable cutoff value that can be passed to ppr_set_tracking_cutoff. This is the most restrictive tracking cutoff.

See also: Tracking Cutoff

Structure Types

ppr_tracked_object_type

typedef struct
{
  int index;
  double time_stamp;
  int tracked_id;
  int track_confidence;
  ppr_object_type object;
} ppr_tracked_object_type;

This structure represents a single object currently tracked by the SDK.

int index

Frame number to which this object instance corresponds. Frames are numbered consecutively starting at zero with each new call to ppr_track_objects or ppr_detect_and_track_objects.

double time_stamp

Number of seconds elapsed between 12:00 am, January 1, 2006 and the time the associated frame was submitted to ppr_track_objects or ppr_detect_and_track_objects. This is an absolute time stamp that is computed from the system's internal clock.

int tracked_id

A unique identifier assigned by the tracker to each object track.

int track_confidence

Confidence of this object track. Object tracks are categorized into four confidence levels, with 0 being the lowest confidence, and 3 being the highest confidence. As tracks evolve, the confidence level will typically change.

ppr_object_type object

Additional data pertaining to the tracked object.

See also: Results, Objects

Back to top.

Average dimensions of the tracked object.

float min_confidence

Track Functions

ppr_track_objects

ppr_error_type ppr_track_objects( ppr_context_type  context,
  ppr_image_type  image,
  ppr_object_list_type  object_list);
Parameters

context - handle to context

image - image in which objects were detected

object_list - objects detected in image

Returns

error code

Restrictions

Tracking must be enabled

Context must be initialized

Submits objects from a single frame to the tracker. The objects must have been previously detected in the input image using ppr_detect_objects. Active tracks are updated with the provided objects. The first frame submitted is frame index zero, and frames are numbered consecutively with each new call.

The ppr_detect_and_track_objects function can be used to do detection and tracking in one function call rather than making separate function calls for detection and tracking. However, for certain threading schemes, it may be desirable to do detection and tracking as separate calls.

Tracking results are obtained by querying ppr_get_completed_tracks and/or ppr_get_current_frame_objects.

Note

Consecutive frames must have the same dimensions. To pass frames of different dimensions (e.g., a new image sequence), the tracker must first be reset by calling ppr_reset_tracker.

See also: Detect and Track Calls, Results, Objects, Image Types

Back to top.

ppr_detect_and_track_objects

ppr_error_type ppr_detect_and_track_objects( ppr_context_type  context,
  ppr_image_type  image);
Parameters

context - handle to context

image - image to search

Returns

error code

Restrictions

Tracking must be enabled

Context must be initialized

Submits a new video frame to the detector and tracker. After searching the provided image for objects of interest, single-frame results are used to update active tracks. The first frame submitted is frame index zero, and frames are numbered consecutively with each new call. If the landmark detector is set to PPR_AUTOMATIC_LANDMARKS, this function also does landmark detection and, when results are requested from the tracker, the landmark fields will be populated with all landmarks that were detected.

Tracking results are obtained by querying ppr_get_completed_tracks and/or ppr_get_current_frame_objects.

Note

Consecutive frames must have the same dimensions. To pass frames of different dimensions (e.g., a new image sequence), the tracker must first be reset by calling ppr_reset_tracker.

See also: Detect and Track Calls, Results, Objects, Image Types

Results Functions

ppr_get_current_frame_objects

ppr_error_type ppr_get_current_frame_objects( ppr_context_type  context,
  ppr_tracked_object_list_type  *tracked_object_list);
Parameters

context - handle to context

tracked_object_list - pointer to structure containing the objects detected/tracked in the most recently submitted frame

Returns

error code

Restrictions

Tracking must be enabled

Context must be initialized

Extracts objects that were detected and tracked in the most recently submitted frame. This function call does not alter the internal state of the tracker. The resulting tracked object list must be freed with ppr_free_tracked_object_list.

Note

This function is provided to enable applications that require results immediately after a frame is processed (see Current Tracks). The results returned from this function call are not finalized. As such, once the tracks associated with the current-frame object are finalized (i.e., rejected or completed), the data corresponding to the current frame can change. If results are not required immediately after frames are processed, the ppr_get_completed_tracks interface should be used instead.

See also: Current Tracks

Back to top.

ppr_get_completed_tracks

ppr_error_type ppr_get_completed_tracks( ppr_context_type  context,
  ppr_completed_track_list_type  *completed_track_list);
Parameters

context - handle to context

completed_track_list - pointer to list of tracks that have been completed

Returns

error code

Restrictions

Tracking must be enabled

Context must be initialized

Extracts tracks that have completed. This function can be called periodically or after all frames in a particular sequence have been submitted to the tracker. Once returned, completed track data internal to the tracker is discarded.

The returned data structure must be freed with ppr_free_completed_track_list.

Until completed tracks are extracted, the tracker will not discard internally managed tracks. To avoid continually increasing memory usage, long-running applications should periodically extract and free completed tracks.

In order to be certain that a particular track has completed (e.g., that an object has left the scene), a small delay is required before tracks are marked complete. This means that an object will leave the scene some number of frames prior to the corresponding track being returned. To force the completion of any tracks and note the end of a video sequence, be sure to call ppr_finalize_current_tracks.

See also: Completed Tracks

Back to top.

ppr_finalize_current_tracks

ppr_error_type ppr_finalize_current_tracks( ppr_context_type  context);
Parameters

context - handle to context

Returns

error code

Restrictions

Tracking must be enabled

Context must be initialized

Forces completion of all active tracks. Low-confidence active tracks are discarded, and high-confidence active tracks are moved to the completed track list. This function should be called between frames when it is known that a track cannot cross the frame-to-frame boundary. For example, this function should be called after processing one video sequence, before processing a different video sequence. After calling, completed tracks may be extracted with ppr_get_completed_tracks.

See also: Current Tracks, Completed Tracks

Back to top.

ppr_get_dispersed_frontal_objects_from_track

ppr_reset_tracker

ppr_error_type ppr_reset_tracker( ppr_context_type  context);
Parameters

context - handle to context

Returns

error code

Restrictions

Tracking must be enabled

Context must be initialized

Resets the tracker to its initial state. All internal memory is freed, any unreturned tracks are discarded, and the frame index is set back to zero. This function should be called between video sequences if multiple sequences are submitted in series using the same context. It also needs to be called any time the image dimensions must change from one image to the next. All of the context's existing settings remain intact.

Flatten / Unflatten Functions

ppr_flatten_tracked_object_list

ppr_error_type ppr_flatten_tracked_object_list( ppr_context_type  context,
  ppr_tracked_object_list_type  tracked_object_list,
  ppr_flat_tracked_object_list_type  *flat_tracked_object_list,
  const char  *source_file_name);
Parameters

context - handle to context

tracked_object_list - tracked object list to flatten

flat_tracked_object_list - pointer to flattened tracked object list

source_file_name - null-terminated string specifying the file name of the source file that generated the tracked object list

Returns

error code

Restrictions

Tracking must be enabled

Flattens a tracked object list, writing all of its internal data to a buffer. This is useful for applications that must write tracked object lists to output sources other than the file system, such as a database. The flattened tracked object list can be converted back to a regular object list using ppr_unflatten_tracked_object_list. The flattened tracked object list must be freed using ppr_free_flat_tracked_object_list.

Free Functions

The provided free functions must be used to free the data structures returned from SDK functions. The user should not try to free these structures using their own free statements. Likewise, if the user allocates their own memory using the provided data types, the user must free that memory themselves rather than calling these free functions. This ensures that the same libraries are used for allocation and freeing.
