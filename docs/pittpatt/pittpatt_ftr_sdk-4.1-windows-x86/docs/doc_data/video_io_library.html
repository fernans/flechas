The PittPatt Video I/O Library provides a simple interface based on FFmpeg for decoding frames from videos and encoding frames to create new videos. Using the decoding interface, raw image data can be extracted on a frame-by-frame basis for submission to other PittPatt SDKs. The encoding interface can be used to create videos that show results produced by other PittPatt SDKs. Please note that this library does not (currently) support any form of seeking in the videos.

It is important to also read the PittPatt Raw Image Library Documentation because the PittPatt Video I/O Library depends on it, and it includes very important information about Memory Management.

1. Introductory Topics

Supported Formats

Decoding

The PittPatt Video I/O Library supports decoding from a number of common video formats, including but not limited to:

  • MPEG-1/MPEG-2 (.mpg)
  • MPEG-4, including H.264 (.mp4)
  • Flash Video (.flv)

The library also partially supports decoding from a wider range of other formats listed below. However, because of variability in the encoding of these formats, the library is not guaranteed to work for every file in one of these formats:

  • AVI (.avi)
  • QuickTime (.mov)
  • Motion JPEG (.mjpeg)
  • Matroska File Format (.mkv)
  • Windows Media Format, older versions (.wmv, .asf)
  • 3rd Generation Mobile System Format (.3gp)
  • Digital Video (.dv)
  • DivX (.divx)

Back to top.

Encoding

The library supports encoding using the following formats:

  • MPEG-4 (.mp4)
  • WMV2 (.avi)

Back to top.

Frame Indices

Video frame indexing starts at zero. Immediately after a video is opened for decoding by calling ppr_video_io_open, the current index is zero. The frame at index zero can then be acquired by calling ppr_video_io_get_frame. There is no need to call ppr_video_io_step_forward before getting the frame at index zero. Each time the video is stepped forward, the frame index is incremented by one. In other words, when decoding a video, ppr_video_io_get_frame_index returns the index of the frame that is currently available.

Immediately after a video is created for encoding by calling ppr_video_io_create, the current frame index is -1 because the video contains no frames. Each call to ppr_video_io_add_frame increments the frame index by one. After the first frame is added, the current frame index is zero because the video contains exactly one frame. In other words, when encoding a video ppr_video_io_get_frame_index returns the index of the most recently added frame.

Back to top.

Bit Rate

For encoding videos, a bit rate must be specified, which determines both the file size and quality of the resulting encoding. If file size is important, experiment with various bit rates to find the best trade-off between size and quality. For applications where file size is less important, use a conservative setting which will result in large file sizes but full quality. As a starting point, 1000 kb/s is an appropriate bit rate for a typical 640x480 video. For larger videos (e.g. high-definition video), the bit rate must be increased appropriately.

Back to top.

Frame Rate

Video frame rates are expressed as two integer values (a numerator and a denominator). Dividing the numerator by the denominator gives the frame rate. When creating a video for encoding, the ppr_video_io_create function must be passed integer values for the numerator and denominator. Although selecting the values by hand to match the desired frame rate is possible, it is often the case that the desired frame rate for an output video is based on the frame rate of another video. Call ppr_video_io_get_frame_rate to get the frame rate of an existing video, expressed as a numerator and denominator. Then use those values when creating a video for encoding.

2. Video I/O Framework

A framework for using the PittPatt Video I/O Library is described below. This framework provides an introduction to the order in which functions should be called, with links to each function's detailed description.

Decoding

  1. Open a video for reading

    Call ppr_video_io_open to open the video to be decoded.

  2. Check to see if a frame is available

    Call ppr_video_io_is_frame_available to see if there is a frame to be read.

  3. Read a single frame from the video

    If a frame is available, it can be read from the video using ppr_video_io_get_frame. This returns a raw image for the available frame.

  4. Process the video frame

    Perform whatever processing is required on the extracted video frame.

  5. Free the video frame

    When the frame is no longer needed, call ppr_raw_image_free to avoid a memory leak.

  6. Advance to the next frame in the video

    Call ppr_video_io_step_forward to advance the video by one frame.

  7. Repeat steps 2-6 until the desired portion of the video has been processed.

    The ppr_video_io_is_frame_available function will return PPR_VIDEO_IO_FALSE when there are no more frames left in the video.

  8. Close the video

    Call ppr_video_io_close when the video is no longer needed.

Back to top.

Encoding

  1. Create a video for writing

    Call ppr_video_io_create to create a video to be encoded.

  2. Add frames to the video

    Call ppr_video_io_add_frame repeatedly until all frames have been added to the video. There is no need to advance the video after adding a frame.

  3. Close the video

    Call ppr_video_io_close after all frames have been added to the video. This finalizes the encoding process.

3. Types Reference

The types described in this section are declared in pittpatt_video_io.h.

Basic Types

ppr_video_io_type

typedef struct ppr_video_struct* ppr_video_io_type;

The ppr_video_io_type represents a single video context used for either decoding or encoding. This handle references private data that is maintained internally to the PittPatt Video I/O Library and is the first argument to most functions. A video decoding context is created by calling ppr_video_io_open. A video encoding context is created by calling ppr_video_io_create.

Back to top.

Enumerated Types

ppr_video_io_logging_type

typedef enum 
{
  PPR_VIDEO_IO_QUIET,
  PPR_VIDEO_IO_VERBOSE
} ppr_video_io_logging_type;

This type is used to indicate whether debugging data should be written to standard output. Call ppr_video_io_set_logging_type to specify the desired setting. The default setting is PPR_VIDEO_IO_QUIET.

Back to top.

ppr_video_io_boolean_type

typedef enum 
{
  PPR_VIDEO_IO_FALSE,
  PPR_VIDEO_IO_TRUE
} ppr_video_io_boolean_type;

This type provides a true/false value that is returned by the ppr_video_io_is_frame_available function.

Back to top.

ppr_video_io_error_type

typedef enum 
{
  PPR_VIDEO_IO_SUCCESS,
  PPR_VIDEO_IO_FAILURE,
  PPR_VIDEO_IO_INVALID_ARGUMENT,
  PPR_VIDEO_IO_OUT_OF_MEMORY,
  PPR_VIDEO_IO_UNSUPPORTED_FORMAT,
  PPR_VIDEO_IO_UNSUPPORTED_CODEC,
  PPR_VIDEO_IO_NO_MORE_FRAMES,
  PPR_VIDEO_IO_DECODING_ERROR,
  PPR_VIDEO_IO_SEEK_ERROR,
  PPR_VIDEO_IO_FILE_NOT_FOUND,
  PPR_VIDEO_IO_ENCODING_ERROR,
  PPR_VIDEO_IO_REQUIRED_INPUT_VIDEO,
  PPR_VIDEO_IO_REQUIRED_OUTPUT_VIDEO,
} ppr_video_io_error_type;

This type represents all error codes that can be returned by the PittPatt Video I/O Library functions. A string version of each error code can be obtained by calling ppr_video_io_error_message.

ppr_video_io_open

ppr_video_io_error_type ppr_video_io_open( ppr_video_io_type  *video,
  const char  *file_name);
Parameters

video - pointer to a currently unused video context variable

file_name - null-terminated string specifying the name of a video file

Returns

error code

Restrictions

none

Opens the video file specified by file_name for reading. When the video will no longer be used, it must be closed by calling ppr_video_io_close.

The first frame can be extracted immediately with ppr_video_io_get_frame after opening the video. Stated another way, the ppr_video_io_step_forward function does not need to be called before extracting the first frame.

See also: Decoding Formats, Frame Indices

ppr_video_io_error_type ppr_video_io_create( ppr_video_io_type  *video,

  int  frame_rate_numerator,
  int  frame_rate_denominator);

video - pointer to a currently unused video context variable

file_name - null-terminated string specifying the name of the video file to create

bit_rate_kbps - bit rate (in kilobits per second) to use for the output video being created

frame_rate_denominator - denominator value for setting the frame rate of the video being created

error code

none

Creates a new video file with the provided file_name. Frames can then be added to the video using ppr_video_io_add_frame. When all frames have been added, the video must be finalized by calling ppr_video_io_close.

Navigation Functions

ppr_video_io_is_frame_available

ppr_video_io_boolean_type ppr_video_io_is_frame_available( ppr_video_io_type  video);
Parameters

video - a video opened for reading

Returns

PPR_VIDEO_IO_FALSE

PPR_VIDEO_IO_TRUE

Restrictions

Cannot be called on videos created for writing

Indicates whether a frame is available to be extracted into an image buffer. This becomes false after either the library failed to decode the next frame (an error occurred), or no more packets were found (the video ended). If this function is called on a video that was created for writing, PPR_VIDEO_IO_FALSE is returned.

ppr_video_io_step_forward

ppr_video_io_error_type ppr_video_io_step_forward( ppr_video_io_type  video);
Parameters

video - a video opened for reading

Returns

error code

Restrictions

Cannot be called on videos created for writing

Decodes the next frame and advances the current frame index by one. The next time ppr_video_io_get_frame is called, it returns a new frame. If ppr_video_io_get_frame is called twice without stepping forward between calls, a duplicate frame is returned from the second call.

ppr_video_io_get_frame

Parameters

video - a video opened for reading

error code

Restrictions

Cannot be called on videos created for writing

Extracts the current frame into a frame buffer. Any necessary color conversion is performed at this point. All frames are extracted into a PPR_RAW_IMAGE_RGB24 formatted buffer. The user must free the frame using ppr_raw_image_free.
